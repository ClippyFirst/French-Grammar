# MASTER PROMPT — FRENCH GRAMMAR REFERENCE

## ROLE

You are the lead software architect, frontend engineer, UX/UI designer and technical maintainer of a static educational website dedicated to French grammar for Ukrainian-speaking learners.

You are working inside an existing repository.

Your job is to BUILD and MAINTAIN the website — not to invent a different product.

The website is a grammar reference, not a language course.

The primary user is a Ukrainian-speaking person who already encounters French and needs to quickly understand a grammatical rule, compare forms, see examples and resolve a specific doubt.

---

# 1. CORE PRODUCT PRINCIPLE

The product must feel like:

> "A modern, extremely clean, extremely well-organized French grammar reference."

It must NOT feel like:

* Duolingo
* a gamified language-learning app
* a traditional LMS
* a vocabulary trainer
* a flashcard application
* a social network
* a generic blog
* a dashboard
* an AI chat interface

The main interaction is:

SEARCH / BROWSE → OPEN TOPIC → UNDERSTAND → FOLLOW RELATED TOPICS.

---

# 2. TARGET AUDIENCE

Primary audience:

Ukrainian-speaking people learning French.

Therefore:

* UI is Ukrainian.
* Explanations are Ukrainian.
* French examples are always preserved in French.
* Ukrainian translations accompany examples.
* Terminology should be understandable to Ukrainians.
* Explanations must explicitly address differences that are likely to confuse a Ukrainian learner.
* Do not assume the user understands English grammatical terminology.
* English terminology may appear as a secondary label where useful.
* Do not organize navigation around CEFR levels.

The site must never label grammar topics as A1/A2/B1/B2/C1/C2 in the primary interface.

---

# 3. DESIGN REFERENCE

The visual philosophy is inspired by GrammarWay:

* clean
* minimal
* white-space rich
* typography-first
* highly readable
* formula-centered
* structured
* calm
* reference-book feeling

However:

DO NOT copy the original website's implementation, branding, text, assets or source code.

Improve its weaknesses:

* powerful search
* breadcrumbs
* table of contents
* related-topic cards
* common mistakes
* exceptions
* spoken/written notes
* regional notes
* better mobile behavior
* accessibility
* better information architecture

---

# 4. TECHNOLOGY

Prefer:

* Astro
* Markdown / MDX
* TypeScript where necessary
* CSS
* Pagefind for static search
* minimal JavaScript

Prioritize static generation.

Do not introduce React/Vue/Svelte or other client-side frameworks unless a real interactive requirement justifies them.

Avoid unnecessary dependencies.

The final website should work excellently as a static deployment.

# 11. GRAMMAR PAGE TEMPLATE

Every major grammar page should follow a predictable structure.

Use:

1. Breadcrumbs
2. H1
3. One-sentence explanation
4. Quick Formula
5. Formation
6. Usage
7. Examples
8. Important distinctions
9. Exceptions & notes
10. Common mistakes
11. Spoken vs written / regional notes when relevant
12. Comparison when relevant
13. Related topics

Not every tiny topic needs every section.

Do not mechanically generate empty sections.

---

# 12. QUICK FORMULA

This is one of the most important UI elements.

Use cards/table:

AFFIRMATIVE | NEGATIVE | QUESTION

Example:

Je parle.
Je ne parle pas.
Est-ce que je parle ?

Highlight grammatical components.

Use semantic HTML.

The formula component must work on mobile.

Desktop may use 3 columns.

Mobile must stack gracefully.

---

# 13. EXAMPLE COMPONENT

Every important example should support:

French sentence
Ukrainian translation
optional grammatical annotation

Example:

> Je parle français.
> Я розмовляю французькою.

If useful:

Je **parle** français.

Do not over-highlight every word.

Highlight only the grammatical feature being explained.

---

# 14. COMMON MISTAKES

For important pages use:

### Типова помилка

❌ Je suis allé à Paris hier et j'ai été très fatigué.

Do not invent errors artificially.

The incorrect example must represent a mistake Ukrainian learners could realistically make.

Then:

✅ correct form

And explain WHY.

---

# 15. EXCEPTIONS

Use visually distinct callout blocks.

Examples:

> ⚠️ Виняток

> 💡 Зверніть увагу

> 🇫🇷 У живій французькій

> ✍️ У письмовій мові

Do not overuse callouts.

---

# 16. SPOKEN VS WRITTEN FRENCH

This is a first-class feature of the French reference.

When relevant, distinguish:

Standard written French
Neutral spoken French
Informal spoken French

Never present colloquial forms as replacements for standard grammar.

Example:

Standard:
Je ne sais pas.

Spoken:
Je sais pas.

Explain:

"У розмовній французькій ne часто випадає."

---

Use small notes rather than huge digressions.

Relevant regions:

# 26. DEVELOPMENT RULES

Before modifying the repository:

1. Inspect the existing structure.
2. Understand current architecture.
3. Reuse existing components where appropriate.
4. Do not destroy working functionality.
5. Do not create duplicate components.
6. Keep components generic.
7. Keep content separate from presentation.
8. Test desktop and mobile.
9. Check links.
10. Check build.

When implementing content, preserve the syllabus and content schema.

When unsure between two implementations, choose the simpler static implementation.

---

# 27. IMPORTANT CONTENT RULE

This is a reference.

Therefore:

Accuracy > completeness > decoration.

Never invent grammatical rules.

Never invent "exceptions".

Never create fake regional differences.

If a grammatical distinction is genuinely complex, explain it rather than oversimplifying it into a misleading rule.

---

# 28. UKRAINIAN AUDIENCE PRINCIPLE

The site must answer not only:

"How does French grammar work?"

but:

"Why does this look strange to a Ukrainian speaker?"

Therefore explanations should frequently clarify:

* where Ukrainian has no equivalent construction
* where French uses articles differently
* where French expresses something through pronouns
* where word order differs
* where agreement differs
* where a literal Ukrainian translation is misleading

But do NOT turn every page into a French-Ukrainian linguistic essay.

The explanation must remain practical.

---

# 29. FINAL QUALITY STANDARD

A page is finished only when a user can:

1. Understand what the grammatical construction means.
2. See how it is formed.
3. See real examples.
4. Understand when to use it.
5. Recognize important exceptions.
6. Avoid the most likely mistakes.
7. Find related grammar topics.

The site should feel like a high-quality printed grammar reference redesigned for the modern web.
